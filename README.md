# QR Decoder by QRGenie

Chrome extension that reads QR codes you see on screen. Chrome can generate a QR code for the current page but cannot read one; this fills that gap.

Made by [QRGenie](https://qrgenie.app), our iOS QR code app. Everything decodes on your device: no analytics, no accounts, no network requests at runtime.

## What it does

- Right-click any image on a page and choose **Decode QR code in this image**.
- Right-click anywhere (or use the toolbar popup) and choose **Scan area for QR code**, then drag a box around the code. This works for QR codes that are not images: video frames, canvas drawings, PDFs rendered in the page, shared screens.
- The result appears in a small card on the page with the decoded content, a **Copy** button and, for web links, an **Open link** button. Links are always shown in full first and never opened automatically.
- Wi-Fi, contact, email, phone, SMS, location and calendar payloads are recognized and their fields shown.

## How decoding works

All decoding runs locally with a vendored copy of [jsQR](https://github.com/cozmo/jsQR) (see `LICENSES.md`). For a right-clicked image the extension first asks the page for the image pixels at natural resolution; if the page's security rules do not allow that (cross-origin images), it falls back to taking a screenshot of the visible tab and cropping to the image's on-screen rectangle. The area scan always uses the screenshot path. Screenshots stay in memory and are discarded after decoding.

Because of the screenshot fallback, a very small QR code on screen may fail to decode; zooming the page and scanning again fixes that.

## Install (load unpacked)

1. Clone or download this repository.
2. Open `chrome://extensions` in Chrome.
3. Turn on **Developer mode** (top right).
4. Click **Load unpacked** and select the repository folder.
5. Pin the extension if you want the toolbar button visible.

To try it, open `test/fixtures/url.png` in a tab (drag the file into Chrome), right-click it and choose **Decode QR code in this image**.

## Permissions

- `contextMenus`: the two right-click menu items.
- `activeTab`: read the current tab only after you invoke the extension, used for the screenshot decode path.
- `scripting`: inject the selection overlay and the result card into the page, on demand.

No host permissions, no content scripts running in the background, no storage, no network access at runtime.

## Project layout

```
manifest.json          Manifest V3 definition
background.js          Service worker: menus, capture, decoding, routing
common/payload.js      Classifies decoded payloads (URL, Wi-Fi, contact, ...)
content/overlay.js     Result card, injected on demand
content/area-select.js Drag-to-select overlay for the area scan
popup/                 Toolbar popup
viewer/                Fallback result page for pages we cannot inject into
vendor/jsQR.js         Vendored decoder (Apache 2.0, see LICENSES.md)
icons/                 Extension icons, generated by scripts/make-icons.js
scripts/               Icon and test fixture generators
test/                  Node test suite and committed fixture images
```

## Development

- `npm test` runs the test suite (Node 18 or newer, no dependencies): jsQR against the committed fixture images, plus the payload classifier.
- `npm run check` syntax-checks every script.
- `npm run make:icons` regenerates the icons (no dependencies).
- `npm run make:fixtures` regenerates the fixtures; needs `npm install --no-save qrcode` first.

There is no build step. The files in the repository are exactly what Chrome loads.
